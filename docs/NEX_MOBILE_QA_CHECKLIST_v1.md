# NEX Mobile QA Checklist v1

## 1) Purpose
Use this checklist to validate whether a newly built NEX page truly meets mobile-first quality before approval.

## 2) First Viewport Check
- Is the page purpose clear in the first mobile viewport?
- Is the main value or task understandable quickly?
- Is the primary CTA visible early enough?

## 3) Layout Check
- Is the layout single-column or cleanly stacked on mobile?
- Is there any horizontal scrolling?
- Are any sections overly dense or visually confusing?
- Does the page read in a clear top-to-bottom flow?

## 4) CTA Check
- Is there one clearly dominant primary CTA?
- Do secondary actions stay secondary?
- Are there any competing high-emphasis actions?

## 5) Typography Check
- Are headings readable on mobile?
- Are text blocks short enough to scan?
- Is the hierarchy clear without needing guesswork?

## 6) Touch / Interaction Check
- Are buttons easy to tap?
- Are links and controls spaced well enough?
- Are interactive elements usable without precision tapping?

## 7) Form Check
- Is the form single-column?
- Are labels clear?
- Are only necessary fields included?
- Is submit action clear?

## 8) Color / Visual Role Check
- Is background usage aligned with NEX color roles?
- Are white/light surfaces used appropriately?
- Is orange reserved for primary CTA emphasis?
- Is navy used structurally rather than everywhere by default?
- Are there too many dark-heavy sections in sequence?

## 9) Content Density Check
- Does each section have one main job?
- Are there too many choices shown at once?
- Are cards or grids too dense?
- Is any block trying to explain too much at once?

## 10) Page-Type Check
- Is the page type explicitly defined?
- Does the layout fit that page type?
- Is the page accidentally behaving like another page type?

## 11) Consistency Check
- Are approved tokens used?
- Are components consistent with NEX standards?
- Is spacing consistent?
- Is there any obvious style drift?

## 12) Release Recommendation
A page is ready to move forward only if:
- It passes the checks above
- It works on the new test URL
- It does not require changing the old route directly
- It is approved before replacement planning
