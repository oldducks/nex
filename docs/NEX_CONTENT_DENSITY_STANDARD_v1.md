# NEX Content Density Standard v1

## 1) Purpose
This document defines how much content should appear in each page, section, and component so that NEX pages remain clear, fast to understand, and suitable for mobile-first use.

## 2) Core Principle
NEX pages must reduce cognitive load.
Users should not need to sort through excessive text, too many choices, or dense visual blocks to understand what to do.

## 3) Density Rules by Page Layer
### 3.1 First viewport
The first mobile viewport must contain only what is necessary to answer:
- What is this?
- Why should I care?
- What should I do next?

### 3.2 Section level
- One section = one message or one job.
- Avoid stacking multiple arguments inside the same visual block.
- If a section becomes too dense, split it.

### 3.3 Component level
- One card should contain one primary idea.
- One CTA block should contain one main action.
- One form step should ask for one logical group of inputs.

## 4) Copy Density Rules
- Headlines must be short enough to scan quickly.
- Support text must be concise.
- Paragraphs must be broken into smaller readable units.
- Avoid large walls of text on mobile.
- If long explanation is necessary, structure it into clear subsections.

## 5) Choice Density Rules
- Do not present too many equally weighted choices at once.
- Gateway pages must limit visible choices.
- Dashboards may show more tools, but they must be grouped and prioritized.
- Forms must ask only for necessary information.

## 6) Visual Density Rules
- Avoid too many cards in one viewport.
- Avoid too many high-contrast blocks stacked together.
- Use spacing to separate thinking units.
- Do not rely on dense icon grids as a substitute for information hierarchy.

## 7) CTA Density Rules
- One dominant CTA per section or decision moment.
- Secondary actions are allowed only when clearly subordinate.
- Do not place multiple strong orange CTAs that compete in the same area.

## 8) Explanation Density Rules
When presenting a concept-heavy page:
- Start with a simple hook
- Introduce the problem or context
- Explain the concept progressively
- End with a clear action

Do not dump all insight at once.

## 9) Dashboard Density Rules
For logged-in tool pages:
- Show most-used actions first
- Group tools by task type
- Reduce equal weighting among all tools
- Keep status and action areas distinct

## 10) Reduction Rule
When in doubt, reduce before adding.
Clarity is more important than completeness in the first reading layer.

## 11) Acceptance Criteria
A page or section passes this standard when:
- It is understandable quickly
- It does not overwhelm the user on mobile
- Its choices are prioritized
- Its text blocks are readable
- Its visuals support hierarchy instead of creating clutter
